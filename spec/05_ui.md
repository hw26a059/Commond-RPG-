# 5. UI・画面設計（ログ仕様含む）

本作は、画面遷移を必要とせず、すべての戦闘情報がリアルタイムで整理・一元管理された「１画面構成（PC基準）」を採用します。また、PCブラウザ閲覧時に画面が縦に長くなり見づらくなることを防ぐため、縦の長さを従来比約3分の1程度に圧縮した「極めてコンパクトな省スペース・レイアウト」を適用しています。

## 5.1 画面の基本レイアウト（PC想定）
PCの大画面ディスプレイ環境を想定し、左右または上下 of 分割配置により、視線移動を最小限に抑えた機能的なレイアウトを構成します。

### レイアウト構成案
```
+-------------------------------------------------------------+
|               【突発フィールドイベントバナー】 (省スペース)  |
+------------------------------+------------------------------+
|                              |                              |
| 【戦況・ステージ表示エリア】  |        【戦闘ログ】          |
| ・プレイヤー3体ステータス    |                              |
|   (HP/MP/SP極小バー表示)     |  ・直近の5行を高さを抑えて   |
|                              |    表示                      |
| ・敵モンスター3体ステータス  |                              |
|   (クリック選択対象、HPバー) |                              |
|                              |                              |
+------------------------------+                              |
| 【コマンドスロット構築】     |                              |
| ・キャラ毎に [技A] [技B] を  |                              |
|   横並びで配置し縦幅短縮     |                              |
| ・固有能力トグルボタン       |                              |
| ・[ターン同時実行] ボタン    |                              |
+------------------------------+------------------------------+
```

### 縦幅削減のための具体的なUI調整ルール
1. **パディング・余白の極小化**:
   - 各コンポーネントの `p-5`、`p-6` など広めの内余白を `p-2.5` や `p-1.5` などの極小パディングへ縮小。
   - 要素間の行間バインディング（`space-y-6` などのギャップ）を `space-y-2` 程度に引き下げ、画面全体の余白を限界までカット。
2. **コマンド構築の横並び化**:
   - 技A選択スロットと技B選択スロットを縦配置から「横並び（2カラム。`grid-cols-2`）」に変更し、キャラクター1人あたりのUI占有縦幅を大幅に削減。
3. **ステータス情報の高密度圧縮**:
   - HP/MP/SPバーの高さを `h-1` や `h-1.5` 等に細線化。
   - ラベルテキストは `HP:◯/◯` などの1行結合レイアウトを採用し極小フォント（`text-3xs` / 0.65rem程度）で表示。
4. **イベントバナーの極小化**:
   - 高さをバナー風にするのではなく、極細のテキストバー（`py-1` 程度）にすることでナビゲーション性を確保しつつ高さを抑える。
5. **戦闘ログの縮小**:
   - 最小高さを `140px` から `90px` へ引き下げ、文字サイズを `text-3xs` に設定。

## 5.2 ログ仕様
戦闘進行にともなう情報の混雑を極限まで減らし、最も重要な最新情報に集中できるUIを設計します。

- **行数制限**：**直近の3〜5行のみを表示**します。
- **挙動**：新しいログが追加されると、最も古いログが上から押し出されて順次消去されます（常に最新の3〜5件が表示エリアに残る形になります）。
- **行動ごとの表示ルール**:
  - キャラクターが「技A＋技B＋固有能力」を使用した場合、細切れにステップ表示するのではなく、**1回の行動結果にまとめて一括表示**します。
  - **ログまとめ例**：`[ターン1] キャラクターAの行動：ファイア ＋ 物理攻撃 ＋ 追撃 ＝ 敵に合計 240 ダメージ！`
  - これにより、限られた3〜5行という狭いスペースでも、他のキャラの行動ログが押し流されず、1ターン全体の戦況履歴として綺麗に残ります。
- **視覚的演出**：ダメージ（赤色）、回復（緑色）、突発イベント（黄色・太字）のように、ログのテキストカラーを種類ごとに分けることで一目で判断可能な設計にします。

## 5.3 操作・デバイス仕様
- **プラットフォーム**: **PC**環境を主軸として最適化します。
- **操作方式**: 基本的にマウスによる**クリック操作（直感的なUIボタン選択）**にてコマンドの構築・発動を行います。
- **視覚効果**: コマンドRPGとして、攻撃時やダメージ発生時には、シンプルなフラッシュ・エフェクトや数値ポップアップなどを表現し、爽快感や手応えを感じられるように考慮します。
